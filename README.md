# Morgue Room Horror — 프로그래밍 포트폴리오

> Unity로 제작한 **호러 게임 프로그래밍 포트폴리오**입니다.
> "게임을 만들었다"가 아니라, **"이런 게임 기능을 직접 구현할 수 있다"**를 코드와 시연으로 보여주는 것이 목적입니다.

---

## 📌 한 줄 소개

『8번 출구』 스타일의 관찰 기반 호러 —
**끊김 없이 반복되는 공간(무한 복도) 트릭**과 **랜덤 이상현상 판별 시스템**을
직접 구현·시연하는 1인칭 호러 게임 프로그래밍 포트폴리오.

---

## 🎯 이 포트폴리오의 목적

이 프로젝트는 **기획·아트 포트폴리오가 아니라 프로그래밍 포트폴리오**입니다.

- 완성된 상용 게임을 목표로 하지 않습니다.
- **"게임 기능을 어떻게 설계하고 구현했는가"**를 코드와 시연으로 증명하는 것이 목표입니다.
- 그래서 **넓고 얕게 기능을 나열하기보다, 핵심 기능 하나(공간 반복 트릭)의 구현 완성도**에 집중합니다.

> 보는 사람이 궁금해할 질문은 하나입니다 —
> *"이 사람은 어떤 게임 시스템을, 어떤 방식으로 코딩할 수 있는가?"*
> 이 포트폴리오는 그 질문에 답합니다.

---

## 🧭 기반 컨셉 — 『8번 출구』 스타일

게임의 **기반(뼈대)**은 인기 호러 게임 **『8번 출구 (The Exit 8)』**의 구조에서 가져옵니다.

『8번 출구』의 핵심 재미는 다음과 같습니다:

- 공간을 **돌아다니며 주변을 관찰**하고, "이상현상(異変)"이 있는지 판단한다.
- **이상현상을 발견하면** 왔던 길로 되돌아가고, **없으면** 앞으로 전진한다.
- 이 판단을 반복하며 다음 구역으로 나아간다.

이 구조는 **관찰 → 판단 → 반응**이라는 단순하지만 강한 긴장감의 루프를 만듭니다.
본 포트폴리오는 이 구조를 그대로 가져오되, 프로젝트의 에셋(Morgue Room)을 살려
지하철 통로가 아닌 **영안실/시체안치소의 공간을 반복해서 돌아다니는** 무대로 옮겼습니다.

## ⭐ 핵심 기능 — "끊김 없이 반복되는 공간" 트릭 (메인)

이 포트폴리오의 **주 기능이자 하이라이트**는
8번 출구식 **무한 반복 공간을 구현하는 프로그래밍 트릭**입니다.

플레이어는 영안실 통로를 계속 앞으로 걷는다고 느끼지만,
실제로는 **같은 공간이 순간이동으로 재사용**되고 있습니다.

### 공간 구조와 루프 (구현됨)

```
[복도] ──문──▶ [키패드 방] ──문──▶ [영안실]
(이음새)        (시작·판정)          (관찰)
```

1. **관찰** — 키패드 방에서 시작해 영안실로 들어가 방을 살핀다.
2. **판정** — 키패드 앞에서 상호작용(E) → **O(있음) / X(없음)** UI로 판단한다.
3. **개방** — 판정하면 복도 문의 **잠금이 풀린다.** 문은 자동으로 열리지 않고
   플레이어가 직접 E로 연다. (들어올 때는 등 뒤에서 '쾅' 닫힌다)
4. **이음새** — 복도를 한참 걷다 보면 화면이 **검게 페이드아웃**된다. 완전히 어두워진
   **그 찰나에** 건물이 통째로 반대편 슬롯으로 옮겨가고 플레이어도 함께 스냅된다.
5. **반복** — 밝아지면 다시 영안실 문 앞. 방은 새로운 이상현상으로 재세팅된다.
   **정답 +1 / 오답 0으로 리셋, 8회 연속 성공 시 클리어** (8번 출구 규칙).

### 이 기능이 증명하는 프로그래밍 기술

| 기술 | 내용 |
|------|------|
| 🌀 안전한 순간이동 | CharacterController를 잠깐 비활성화 후 위치·회전 리셋 (물리 간섭 방지) |
| 🕶️ 이음새 숨김 | 어두운 복도 + 트리거 볼륨으로 재배치 순간을 감춰 **끊김 없는 착시** 구현 |
| 🎬 중앙 상태 관리 | GameManager(싱글톤)가 진행도·판정·문·이상현상 세팅을 한곳에서 지휘 |
| 🚪 코드 제어 문 | 잠금/개방 상태를 가진 문 — 플레이어용(E 토글)과 시스템용(자동 개폐)을 한 클래스로 |
| 🖐️ 상호작용 인터페이스 | IInteractable 하나로 문·키패드를 동일하게 처리 (Raycast + 레이어 필터링) |

### 🎥 시연 방식 — "착시 + 원리"를 동시에

이 트릭의 핵심 시연은 **게임뷰와 씬뷰를 동시에** 보여주는 것입니다.

- **게임뷰**: 플레이어는 계속 새로운 공간으로 나아가는 것처럼 보인다 → **착시(결과)**
- **씬뷰(위에서 본 시점)**: 실제로는 플레이어가 같은 공간으로 순간이동되는 것이 드러난다 → **원리(구현)**

> 기획 포폴은 "플레이어가 속는 착시"를 보여주지만,
> **이 포트폴리오는 "그 착시를 엔진 레벨에서 어떻게 만들었는가"**를 그대로 증명하는 것을 목표로 합니다.

## 👁️ 서브 기능 — 랜덤 이상현상 판별 시스템

반복되는 각 공간에는 **이상현상(異変)이 있을 수도, 없을 수도** 있습니다.
이상현상은 **하나의 판정 시스템**으로 관리되며, 그 내용은 **여러 변형 중 랜덤**으로 등장합니다.

- **구현된 변형 4종:** 시체 소실 / 시체 이동(자세 변화) / 시체 증가 / **시체 서랍 전부 열림**
- 플레이어는 **관찰**로 이상현상을 감지하고, 키패드의 **O/X 판정 UI**로 "있다 / 없다"를 판단한다.
- 판정이 **맞으면 진행도 +1**, **틀리면 0으로 리셋**.

| 기술 | 내용 |
|------|------|
| 🎲 랜덤 이상현상 시스템 | AnomalyManager가 등록된 변형 중 랜덤 발동, 방 리셋 시 항상 정상 상태로 완전 복원 |
| 🧩 변형 확장 구조 | 추상 클래스 `Anomaly` 상속으로 변형 추가(Toggle형·Transform형·Slide형) — 매니저 코드 수정 없이 확장 (다형성) |
| 🖥️ 판정 UI | uGUI 버튼 이벤트로 O/X 입력, 열릴 때 커서 해제 + 1인칭 조작 잠금, 닫히면 복귀 (모드 전환 관리) |

> **설계 원칙:** 이상현상은 *"종류는 1개 시스템, 내용은 랜덤 N개"*로 만듭니다.
> 구현은 하나에 집중하되, 플레이는 매번 달라지도록 하기 위함입니다.

## 🔢 진행도 표시 UI — 월드 스페이스(디제틱) UI

현재 연속 성공 횟수를 **키패드 위에 물리적으로 박힌 표시**로 보여줍니다.
화면 구석 HUD가 아니라 **게임 세계 안에 실재하는 UI(디제틱 UI)**라, 플레이어가
키패드를 쳐다봐야 `1 / 8` 같은 숫자를 읽게 됩니다 — 8번 출구의 세계 내 표지판과 같은 방식.

### 작동 방식

- **월드 스페이스 Canvas**가 **활성 방을 따라다닌다**(`FollowActiveRoom`) → 건물이 좌우
  슬롯을 오가도 표시가 늘 키패드 위에 붙어 있다.
  - 🐛 원래는 캔버스가 씬 루트에 고정돼 있어, 건물이 반대편 슬롯에 서는 **짝수 회차마다
    표시가 사라졌다.** 처음 한 번 '활성 모듈 기준 상대 자세'를 기억해두고 매 프레임
    현재 모듈에 다시 적용하는 방식으로 해결.
- `GameManager`가 관리하는 진행도를 매 프레임 읽어 텍스트에 반영. **값 계산·판정은
  GameManager가, '표시'만 여기서** 담당한다 (관심사 분리 — `InteractionPromptUI`와 동일 철학).
- 판정 성공 시 `1 / 8 → 2 / 8` 로 올라가고, 오답이면 `1 / 8` 로 리셋, 목표 도달 시 `CLEAR`.

| 기술 | 내용 |
|------|------|
| 🌍 디제틱 UI | Screen Space HUD가 아닌 **World Space Canvas**를 키패드에 마운트 (렌더 모드 무관 스크립트) |
| 🔗 상태 참조 | `GameManager.Progress` / `ClearGoal`을 읽어 표시만 담당 (로직과 표현 분리) |
| 🔢 표시 오프셋 | `진행도 + 시작 번호(displayOffset)`로 0-기반 값을 **1-기반(`1/8`)** 표시로 변환 — 형식 문자열이 아닌 값으로 제어 |

> **설계 포인트:** 표시 형식(`{0} / {1}`)과 표시 값(진행도+오프셋)을 분리해,
> 시작 숫자를 바꿀 때 형식 문자열의 자리 번호를 건드리지 않고 **숫자 필드 하나로** 조절한다.

## 🕵️ 추격자 — 씬 구조로 푼 문제들

추격자를 넣은 직후 증상이 셋 있었다. **안 보인다 / 누운 채로 다가온다 /
쳐다봐도 안 멈춘다.** 셋 다 코드가 아니라 **씬 구조**가 원인이었고, 그래서
**코드가 아니라 씬으로 고쳤다.** 여기서 얻은 게 이 기능에서 제일 값진 부분이다.

### ① 안 보인다 + ② 누운 채로 다가온다 — 부모가 다른 로컬 좌표

`Stalker`가 등장 자리를 `spawnPoint`의 **로컬 좌표**로 읽고 있었는데,
`spawnPoint`와 추격자의 **부모가 서로 달랐다.** 좌표계가 다르니:

- **위치**가 부모 오프셋(5.4, -0.5, 0.8)만큼 어긋나 바닥 아래로 파묻혔다
- **회전**이 기준점의 무회전으로 덮여, 세워둔 자세(z 90°)가 지워져 **시체가 누웠다**

`TransformAnomaly`에 이미 적어둔 함정과 **똑같은 종류**다 — 로컬 복사는 부모가
같아야만 맞다. 그래서 등장할 때 기준점의 **월드** 자세를 읽도록 바꿨다.

회전 쪽은 코드로도 막을 수 있었지만(보정 쿼터니언을 따로 곱하는 식),
**구조로 푸는 쪽을 골랐다:**

```
Stalker        ← 로직용 루트. 무회전, 피벗은 발바닥. 회전을 덮어써도 안전
└── Model      ← 아트용. 세우는 보정(z 90°)을 여기가 들고 있는다
    └── 표본점(머리·가슴·발)
```

나누지 않으면 `LookRotation`이 매 프레임 보정을 지운다. 나누면 **계산 자체가 사라진다.**

### ③ 쳐다봐도 안 멈춘다 — 자기 몸이 시야를 막고 있었다

차폐 검사의 **출발점이 카메라**인데, 카메라는 **플레이어 몸 안**에 있다.
그래서 첫 히트가 플레이어 자신의 콜라이더로 잡혀, 정면으로 쳐다봐도 영영
"가려짐"이 나왔다. 소품(의자·세면대)까지 전부 시야를 막는 것도 겹쳤다.

**진단 방법 —** 판정이 바뀔 때만 콘솔에 한 줄 남기게 했더니 범인이 바로 나왔다.

```
[Stalker] 시야 판정 → 화면엔 있으나 가림 — Player · 거리 12.4m
[Stalker] 시야 판정 → 화면엔 있으나 가림 — metal_sink · 거리 12.4m
```

**해결 —** 콜라이더를 코드로 걸러내는 대신 **레이어**로 풀었다. `SightBlocker`
레이어를 만들어 **벽·문만** 넣고, 추격자의 `Occluders` 마스크를 그것만으로 좁혔다.

> **마스크는 "빼기"가 아니라 "넣기"로 설계했다.** `Default` 하나로 두면 세상 모든
> 것이 시야를 막아서 하나씩 빼내는 싸움이 된다. 반대로 두면 소품을 새로 추가해도
> 기본이 "안 막음"이라 같은 사고가 재발하지 않는다.

### ④ 물체를 통과한다 — 충돌 응답까지만

좌표를 직접 더하고 있어서 테이블을 관통했다. `CharacterController`로 바꿔
**막히면 표면을 타고 미끄러지게** 했다.

경로탐색은 **의도적으로 범위 밖**이다. `NavMeshSurface`로 두 슬롯을 함께 구우면
가능하긴 하지만, 이 기능에서 증명하려는 건 경로탐색이 아니라 시야 판정이다.
다만 **통과해버리면 '보고 멈춘다'는 규칙 자체가 우스워지므로** 충돌까지는 처리했다.
"어디까지 하고 어디서 멈출지"를 정한 선이 여기다.

### 이 과정에서 얻은 원칙

**씬 설정 문제를 코드로 때우면 버그가 늘어난다.** 실제로 이번에 콜라이더 필터링을
코드로 짰다가 걷어내고 레이어로 옮겼고, 회전 보정도 쿼터니언 계산에서 자식
오브젝트로 옮겼다. 둘 다 **코드가 줄고 사고 여지가 사라졌다.**

| 문제 | 코드로 때우면 | 엔진 기능으로 풀면 |
|---|---|---|
| 특정 콜라이더 제외 | 히트 순회하며 걸러내기 | **LayerMask** |
| 컴포넌트 필수 보장 | null 체크 분기 | **`[RequireComponent]`** |
| 모델 자세 보정 | 쿼터니언 오프셋 계산 | **자식 오브젝트** |

- [ ] 추격자가 테이블·모서리에 **끼어서 못 오는지** — 충돌 응답은 회피가 아니라
      밀어내기라, 갇히면 스폰 위치나 캡슐 반지름(0.3)을 조정한다

### 2. 오답 피드백 (사운드 없이 가능한 부분)

지금은 틀려도 진행도만 조용히 0이 된다. 원작은 되돌아가야 해서 실패가 몸으로
느껴지는데, 여기선 숫자만 바뀌어 **긴장감의 핵심이 빠져 있다.**

소리 없이도 할 수 있는 것: 화면 붉은 점멸, 진행도 UI 흔들림/색 변화,
`ScreenFader` 재활용한 짧은 암전.

### 3. 이상현상 추가 (여유 있으면)

`ToggleAnomaly` / `SlideAnomaly`로 **코드 없이** 가능한 것들:

- 천장 조명 하나 꺼짐 (`ceiling_light` 6개 중 하나 → `hideOnActivate`)
- 소품 소실/증가 (`brain_jar`, `instrument_tray`, `trash_can`) — 시체보다 작아 난이도 높은 변형

> 변형이 늘수록 각 변형의 등장 확률은 낮아진다(4종이면 각 1/4).
> 너무 미묘한 것을 넣으면 플레이어가 못 찾고 억울하게 지므로, 눈에 띄는 것 위주로.

### 4. 튜닝

- `ScreenFader`: Fade Out / Hold / Fade In 시간
- `Door`: `Slam Duration`(0.07) / `Slam Rebound Angle`(6°)
- `SeamTrigger` 위치: 문에서 멀수록 "걷다 보니 어두워졌다"가 자연스러움
- `FirstEntryPoint`: 게임 시작 시 서는 자리·바라보는 방향

### 씬 상태 주의사항 (유지할 것)

- **복도 끝 벽은 막힌 채로 둘 것.** 소켓은 통과하는 문이 아니라 **배치 계산용 기준점**이다.
- `ParkAnchor` 삭제 금지 — 컬링된 건물이 숨는 위치로 필요하다.
- `SeamSocket`은 **위치만** 중요하다. 위아래로 기울이지만 말 것.
- **레이어 규칙** — 추격자 시야 판정이 여기에 통째로 의존한다.
  - `SightBlocker` = **벽·문만.** 소품(의자·세면대)을 넣으면 그 뒤에서 안 멈춘다
  - `Player` = 플레이어. **`SightBlocker`에 넣지 말 것** — 카메라가 몸 안에 있어
    자기 몸이 시야를 막아 영영 '안 보임'이 된다
  - 추격자도 `SightBlocker` 밖에 둘 것 (`CharacterController` 캡슐이 자기 시야를 막는다)
- **추격자 `Model`의 Position은 `(0, 1.055, 0)`** — Y만. X/Z를 주면 **로직 위치와
  보이는 몸이 어긋나** 안 보이는 것에 잡힌다. 등장 자리는 `StalkerPoint`로 정한다.
- 안쪽 이중문은 **완전히 닫힌 자세로 저장**해야 한다 (`Door`가 그 자세를 '닫힘'으로 굳힌다).

### 1️⃣ 1인칭 컨트롤러 — `FirstPersonController.cs`

**기능:** WASD 이동 · 마우스 시점 회전(몸통 Yaw / 카메라 Pitch 분리) · 중력

| 사용한 함수·API | 용도 |
|----------------|------|
| `InputAction` + `AddCompositeBinding("2DVector")` | WASD 4키를 하나의 `Vector2` 입력으로 합성 |
| `moveAction.ReadValue<Vector2>()` | 매 프레임 이동 입력 읽기 |
| `CharacterController.Move()` / `.isGrounded` | 물리 이동 + 바닥 판정 |
| `transform.Rotate()` / `Quaternion.Euler()` | 몸통 좌우 회전 / 카메라 상하 기울임 |
| `Mathf.Clamp()` | 시점이 뒤로 넘어가지 않게 상하 각도 제한 |
| `Vector3.ClampMagnitude()` | 대각선 이동이 √2배 빨라지는 것 방지 |
| `Cursor.lockState` / `Cursor.visible` | 1인칭 조작감(커서 잠금·숨김) |

**설계 포인트:** Yaw(몸통)와 Pitch(카메라)를 분리해 몸은 수평 유지 → 시선 상하가 이동 방향에 영향을 주지 않는 1인칭 정석 구조. 이동 상태(`IsMoving`)와 조작 잠금(`ControlsLocked`)을 프로퍼티로 노출해 손 애니메이션·UI가 참조하게 함.

### 🖐️ 손 애니메이션 — `HandAnimator.cs`

**기능:** 걷기/정지에 따라 손 Idle ↔ Walk 전환

| 사용한 함수·API | 용도 |
|----------------|------|
| `GetComponentsInChildren<Animator>()` | 좌/우 손 Animator를 한 번에 수집 |
| `Animator.StringToHash("IsMoving")` | 파라미터 이름을 해시로 캐싱(매 프레임 문자열 비교 비용 제거) |
| `Animator.SetBool()` | 이동 여부를 Animator에 전달 |

**설계 포인트:** 이동 '판단'은 컨트롤러가, 애니메이션 '반영'은 여기서 → 로직과 표현(연출)을 분리.

### 2️⃣ 상호작용 시스템 — `PlayerInteractor.cs` + `IInteractable.cs`

**기능:** 카메라 정면을 조준해 상호작용 가능한 물체를 감지하고 E로 작동

| 사용한 함수·API | 용도 |
|----------------|------|
| `Physics.Raycast(ray, out hit, range, layerMask, QueryTriggerInteraction.Collide)` | 시선 정면·사거리 내 물체 감지 (트리거 콜라이더도 조준 대상에 포함) |
| `LayerMask` (Interactable 레이어) | 상호작용 대상 레이어만 필터링 |
| `hit.collider.GetComponentInParent<IInteractable>()` | 콜라이더가 자식(문짝)에 있어도 부모의 상호작용 컴포넌트 탐색 |
| `interactAction.WasPressedThisFrame()` | E 입력 감지 |

**설계 포인트:** 대상이 문인지 키패드인지 몰라도 `Interact()` 하나로 처리(인터페이스 다형성). 조준 대상의 안내 문구(`Prompt`)를 UI가 읽어가 화면에 표시. 조준 필터는 **레이어(Interactable)** 로 하고, 조준되면 안 되는 볼륨(복도 순간이동 트리거)은 다른 레이어에 두어 `LayerMask` 단계에서 제외한다.

**해결한 이슈 2건:**
- 🐛 **UI 열린 채 상호작용 유지** — 판정 UI가 열려 커서가 풀린 상태에서도 E로 문이 여닫히던 문제를, `JudgmentUI.IsOpen`일 때 상호작용을 멈추도록 가드를 추가해 해결.
- 🐛 **키패드가 조준되지 않음** — 키패드의 상호작용 콜라이더가 트리거(IsTrigger)라, 트리거를 무시하는 Raycast 설정에서는 조준되지 않던 문제를 `QueryTriggerInteraction.Collide`로 트리거도 잡도록 명시해 해결.

### 🚪 코드 제어 문 — `Door.cs`

**기능:** 경첩식으로 부드럽게 여닫힘. **플레이어용(E 토글)과 시스템용(자동 개폐)을 한 클래스로**

| 사용한 함수·API | 용도 |
|----------------|------|
| `StartCoroutine` / `StopCoroutine` + `IEnumerator` | 프레임에 걸친 문 회전 애니메이션 |
| `Quaternion.Slerp()` | 현재 각도 → 목표 각도 부드러운 보간 |
| `Quaternion.AngleAxis()` | 경첩 축 기준 열림 각도 계산 |

**설계 포인트:** `Interact()`는 잠금(`isLocked`)을 존중하지만, `Open()`/`Close()`는 코드 전용이라 잠금을 무시 → 평소엔 못 여는 복도 문을 `GameManager`가 직접 여닫음. 보간을 현재 각도에서 시작해 여닫는 중간에 방향이 바뀌어도 자연스러움.

### 3️⃣ ⭐ 공간 반복 트릭 — 방 모듈 풀링 + 좌우 슬롯 교대

> 관련 스크립트: `RoomModulePool.cs` · `RoomModule.cs` · `RoomSocket.cs` · `SeamTrigger.cs` · `ScreenFader.cs` · `PlayerTeleporter.cs`

**기능(메인):** 판정 후 복도를 걷다 보면 화면이 암전되고, 밝아지면 다시 영안실 문 앞.
그 암전 사이에 **건물이 통째로 반대편으로 옮겨간다.**

```
판정 → 복도 문 열림 → 복도를 한참 걸음 → SeamTrigger
     → ScreenFader 페이드아웃
     → ▓▓ 완전 암전 ▓▓  ① 현재 건물 컬링(SetActive false) + 대기 위치로
                        ② 다음 건물을 반대쪽 슬롯에 세우고 활성화
                        ③ 플레이어를 새 건물 복도 문 앞으로 스냅
     → 페이드인 → 다시 영안실 문 앞
```

**화면에 존재하는 건물은 언제나 하나뿐이다** — 이것이 이 설계의 핵심 제약이자 강점.

#### 여기까지 온 시행착오 (3안 중 3안 채택)

| 시도 | 방식 | 폐기 사유 |
|------|------|----------|
| 1안 | 방 하나를 통째로 이동 (`RoomLoopMover`) | 방이 하나뿐이라 **자기 자신과 겹침** |
| 2안 | 방 2개를 복도 끝끼리 이어붙임 (소켓 체인) | 두 건물이 동시에 존재 → **이음새를 들킴** |
| **3안** | **한 번에 하나만 + 좌우 슬롯 교대** | **채택** — 동시 존재 자체를 없앰 |

2안은 순간이동도 암전도 없이 "진짜로 걸어서" 이동하는 구조라 기술적으로는 더 매끄러웠지만,
복도 저 끝에 반대편 건물이 실제로 서 있다는 사실을 **눈썰미 좋은 플레이어는 알아챈다.**
착시는 "티가 안 나는 것"이 전부라, 기술적 우아함보다 **들키지 않는 쪽**을 택했다.

| 사용한 함수·API | 용도 |
|----------------|------|
| `Instantiate()` + `SetActive(false)` | **오브젝트 풀링 + 컬링** — 무한 생성 대신 2개 순환, 비활성 건물은 렌더링에서 제외 |
| `Quaternion.LookRotation()` / `Quaternion.Inverse()` | 소켓 지점을 축으로 한 **180° 뒤집기 배치 계산** |
| `Pose` (구조체) | 실측한 좌·우 배치 슬롯을 값으로 보관 |
| `Action` 콜백 (`FadeThrough(onFullyBlack)`) | 페이드가 **완전히 검어진 순간**에만 스왑을 실행 |
| `CanvasGroup.alpha` + `IEnumerator` | 프레임에 걸친 페이드 연출 |
| `CharacterController.enabled = false/true` | **순간이동 순간에만 잠깐 끄고 위치 변경 후 다시 켜기** |
| `OnTriggerEnter(Collider)` | 복도 중간 트리거 볼륨 통과 감지 |

**설계 포인트 ① — 좌표를 씬에 하드코딩하지 않는다.**
좌·우 슬롯을 손으로 찍어두면 복도 길이를 조금만 바꿔도 전부 다시 재야 한다. 대신
모듈이 자기 접합부(`RoomSocket`)를 **스스로 선언**하게 하고, `MeasureSlots()`가 첫 모듈을
자 삼아 "소켓을 축으로 180° 뒤집은 자리"를 실측해 반대편 슬롯으로 쓴다. 모듈 크기가
바뀌어도 씬을 다시 만질 필요가 없다. (모듈러 레벨 조립의 표준 패턴)

**설계 포인트 ② — 배치 계산은 Transform이 아니라 '값'을 받는다.**
`AlignSeamTo()`의 기준이 되는 소켓은 **바로 그 모듈 자신의** 소켓이다. 살아있는
`Transform`을 참조하면 회전을 적용하는 순간 기준점까지 같이 흔들려 계산이 무너진다.
그래서 위치·회전을 값으로 떠서 넘긴다.

**설계 포인트 ③ — 순간이동의 핵심 함정.**
`CharacterController`는 자기 위치를 스스로 관리해서, 켜진 채로 `transform.position`을
바꾸면 무시되거나 충돌로 튕긴다. → **잠깐 비활성화 후 위치를 옮기고 다시 켜는 것**이
안전한 순간이동의 핵심.

**설계 포인트 ④ — 트리거 위치가 곧 연출.**
`SeamTrigger`를 방문 바로 앞에 두면 나오자마자 암전돼 티가 난다. 복도를 **한참 걷다가**
자연스럽게 걸리도록 문에서 충분히 떨어뜨려야 "걷다 보니 어두워졌다"는 느낌이 산다.

### 4️⃣ 랜덤 이상현상 시스템 — `Anomaly.cs`(추상) + `AnomalyManager.cs`

**기능:** *"시스템은 1개, 변형은 N개"* — 방마다 랜덤으로 이상현상 발동, 리셋 시 항상 정상 복원

| 사용한 함수·API | 용도 |
|----------------|------|
| `abstract class` + `abstract void Activate()/Deactivate()` | 모든 변형의 공통 규격 정의(다형성 기반) |
| `Random.value` / `Random.Range()` | 이상현상 유무·종류 랜덤 결정 |
| `GameObject.SetActive()` (`ToggleAnomaly`) | 시체 소실/증가 (켜고 끄기) |
| `Transform.SetPositionAndRotation()` (`TransformAnomaly`) | 시체 이동/자세 변화 (원래 값은 `Awake`에서 자동 저장) |

**구현된 변형 3종:** 시체 소실 · 시체 이동(자세 변화) · 시체 증가
**설계 포인트:** `AnomalyManager`는 `Anomaly` 타입만 알면 되고, 새 변형을 추가해도 매니저 코드는 그대로. 발동 전 항상 `DeactivateAll()`로 완전 복원해 이전 이상현상이 남는 버그를 원천 차단.

**해결한 이슈 2건:**
- 🐛 **모듈 이동 시 시체가 옛 위치로 튐** — `TransformAnomaly`가 정상 자세를 **월드 좌표**로
  저장하던 문제. 건물이 통째로 옮겨가면 시체는 따라 움직이는데 저장값은 그대로라,
  복원할 때 건물이 있던 옛 자리로 날아갔다. **로컬 좌표** 저장으로 전환해 해결.
- 🐛 **첫 방에는 이상현상이 절대 안 나옴** — `AnomalyManager.Start()`의 `DeactivateAll()`이,
  `GameManager.Start()`가 방금 켜준 첫 방 이상현상을 도로 꺼버리던 문제.
  **`Instantiate`로 생성된 오브젝트의 `Start`는 생성한 쪽의 `Start`보다 늦게 돈다**는 것이
  원인. "이미 세팅됐으면 건드리지 않는다" 플래그를 두어 해결.

### 6️⃣ 🎬 중앙 상태 관리 — `GameManager.cs`

**기능:** 진행도(정답 +1 / 오답 0 리셋, 8연속 클리어) · 판정 처리 · 루프 진행 지휘

| 사용한 함수·API | 용도 |
|----------------|------|
| `static Instance` (싱글톤) | 판정 UI·복도 트리거가 쉽게 접근 |
| 상태 필드(`progress` / `judged`) | 진행도 · 중복 판정 방지 |
| `Judge()` → `SetDoorsLocked(false)` → `AdvanceToNextRoom()` → `FadeThrough(DoAdvance)` → `EnterRoom()` | 게임 루프 한 흐름을 한곳에서 조율 |

**설계 포인트 ①:** 각 시스템(문·순간이동·이상현상·페이드)은 자기 일만 하고, **순서와 진행 판단은 `GameManager`가 지휘** → 시스템 간 직접 의존을 줄이고 흐름을 한눈에 파악 가능.

**설계 포인트 ② — 첫 판만은 결국 갈라놓았다.** 원래는 게임 시작과 매 루프가 `EnterRoom()`
하나를 공유했다. "시작할 때만 다르게 도는 경로"가 생기면 첫 판에서만 나는 버그가 따라오기
때문이다(실제로 첫 방 이상현상 버그가 그 종류였다).

하지만 첫 판은 요구사항 자체가 다르다 — 플레이어가 **영안실 안에서** 시작하고, 문은 닫혀
있어야 하며, 이상현상이 없어야 한다(무엇이 '정상'인지 먼저 익혀야 판별이 가능하니까).
공유 경로에 분기를 덧대는 대신 `EnterFirstRoom()`으로 **의도를 이름에 드러내** 분리했다.
경로를 합치는 것 자체가 목적이 아니라, **분기가 숨어드는 것**이 문제였기 때문이다.

**설계 포인트 ③ — 정답을 매니저가 들고 있지 않는다.** "이 방에 이상현상이 있는가"는
`RoomModule.HasAnomaly`가 들고, 매니저는 판정할 때 물어본다. 건물이 2개를 오가는 구조라
매니저에 정답을 캐싱해두면 **어느 건물의 정답인지 어긋나는 순간** 판정이 무너진다.
